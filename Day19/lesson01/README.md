# 1차시. Groq Responses API로 근거 있는 상담 초안 만들기

## 1. 학습목표

[수업 전 안내](../TODAY_GUIDE.md)를 먼저 읽습니다.

- Responses API의 input·instructions·output_text를 구분합니다.
- 확인되지 않은 원인을 지어내지 않는 상담 초안을 만듭니다.

### 앞 차시와 무엇이 달라지나요?

| 출발점 | 이번에 새로 완성할 기능 | 완료 산출물 |
| --- | --- | --- |
| 일반 질문 한 문장에 답하기 | 업무 규칙과 출력 형식이 있는 IT 상담 초안 | 완료 상태·응답 ID·상담 초안 |

기본 코드는 해당 기능이 정상 작동하는 완성 예제입니다. 실행 결과를 먼저 확인하고 업무 조건이나 표시 한 곳을 바꿉니다. 각 차시의 수정 과제는 다음 차시 실행의 전제 조건이 아닙니다.

## 2. 중요 알고리즘 및 코드를 읽을 때 반드시 알아야 할 내용

VPN 연결이 안 된다는 문의를 받았습니다. 단순히 “다시 설치하세요”라는 답변보다 현재 증상, 부족한 정보, 다음에 할 일을 구분한 초안이 필요합니다. 이번 결과물은 바로 전달하기 전에 검토할 수 있는 상담 초안입니다.

`instructions`는 상담자가 지킬 업무 규칙입니다. 확인하지 않은 원인을 단정하지 않고 비밀번호를 요구하지 않는다는 기준을 둡니다. `input`은 이번 문의입니다. `output_text`는 화면에 보여 줄 최종 답변이고, response.id는 요청 결과를 구별하는 번호입니다.

| 코드 값 | 이번 예제에서의 역할 |
| --- | --- |
| GROQ_API_KEY | .env에서 읽는 Groq 인증 키 |
| base_url | Groq의 OpenAI 호환 API 주소 |
| model | openai/gpt-oss-20b |
| instructions | 상담 범위와 세 가지 출력 제목 |
| input | 실제 문의 문자열 |
| response.output_text | 사용자용 답변 텍스트 |

이 차시는 단건 답변의 품질 기준을 만듭니다. 이전 대화 보관은 2차시에서 추가합니다. 모델이 만든 설명을 실제 진단이나 실행 완료로 취급하지 않습니다. 숨은 추론 내용은 화면에 표시하지 않습니다.

### 핵심 코드

```python
response = client.responses.create(
    model=MODEL, instructions=instructions, input=inputs,
    reasoning={"effort": "low"}, max_output_tokens=1600,
)
answer = response.output_text
```

전체 실행 코드는 [main.py](main.py)에 있습니다. 이번 수정 대상은 **INSTRUCTIONS 문자열**입니다. 준비된 인증·통신 코드를 모두 다시 작성하지 않고 현재 기능이 해결하는 문제를 확인합니다.

참고: [Groq Responses API](https://console.groq.com/docs/responses-api), [Groq 프롬프트 패턴](https://console.groq.com/docs/prompting/patterns).

## 3. 코드 제공

### 준비와 실행

Groq 콘솔에서 발급한 본인의 키를 .env의 GROQ_API_KEY에 입력합니다. GROQ_MODEL은 openai/gpt-oss-20b를 사용합니다. 키는 코드·교안·채팅에 적지 않습니다.

Windows CMD에서 현재 차시 폴더로 이동합니다. 경로는 실제 압축 해제 위치에 맞춥니다. 정상 수업 가상환경을 사용하며, 처음 환경 준비는 [서버·환경 안내](../BACKEND_GUIDE.md)를 따릅니다. **기존 .env가 있으면 copy 명령을 생략**합니다.

```bat
cd /d C:\AI4\Groq_MultiTurn_Morning\lesson01
python -m pip install -r requirements.txt
copy .env.example .env
notepad .env
python main.py
```

CMD에 IT 문의:가 보이면 입력합니다. 문의 한 건을 처리하면 프로그램이 끝납니다. 다른 문의는 같은 명령으로 다시 실행합니다.

### 실습 순서

1. `python main.py`를 실행하면 `IT 문의:`가 나옵니다. 아래 문장을 입력합니다.

```text
Windows 11 노트북에서 회사 VPN이 연결 시간 초과로 실패합니다. 비밀번호는 정상이고 재부팅은 이미 했습니다.
```

2. 세 제목으로 나뉜 초안을 읽습니다. 재부팅을 아직 안 했다고 취급하거나 실제 VPN 주소를 지어내지 않는지 봅니다. 응답 ID와 완료 상태를 확인합니다.
3. main.py의 **INSTRUCTIONS 문자열 한 곳**에서 “확인 질문은 최대 2개, 다음 조치는 우선순위가 높은 1개만 제시합니다.”를 추가합니다. 현재 코드는 제목만 정하고 항목 개수는 제한하지 않습니다. 다른 API 호출은 바꾸지 않습니다.
4. 파일을 저장한 뒤 같은 명령과 같은 문의로 다시 실행합니다. 질문과 조치의 개수가 요청한 기준에 맞는지 비교합니다. 개수 준수는 모델 답변을 읽어 평가하는 기준이며 파이썬이 강제한 값은 아닙니다.

### 예상 결과

| 확인할 것 | 예상 결과 |
| --- | --- |
| 첫 화면 | CMD에 IT 문의: 표시 |
| 완료 상태 | completed |
| 사용 모델 | openai/gpt-oss-20b |
| 응답 ID | resp_…처럼 실행마다 달라지는 문자열 |
| 입력이 빈 문자열 또는 1000자 초과 | 문의는 1~1000자로 입력하세요. / API 호출 없음 |
| GROQ_API_KEY를 빈 값으로 저장 | .env에 GROQ_API_KEY와 GROQ_MODEL을 입력하세요. |
| 예시 키 문자열을 그대로 사용 | Groq 호출 실패: 키, 모델 권한, 호출 한도를 확인하세요. |

**AI 답변 예시 — 실제 문장은 달라질 수 있습니다.**

```text
[증상 요약]
Windows 11에서 VPN 연결 시간 초과가 발생하며 재부팅은 이미 시도했습니다.
[확인할 정보]
다른 네트워크에서도 같은가요? 같은 환경의 동료도 같은 증상인가요?
[다음 조치]
발생 시각과 오류 문구를 정리해 사내 IT 문의 채널에 전달해 주세요.
```

합격 기준은 제목 세 개, Windows 11·시간 초과·재부팅 완료 반영, 비밀번호 요구와 원인 단정 없음입니다. 수정 후에는 확인 질문 최대 두 개와 다음 조치 한 개라는 추가 기준도 적용합니다. 예시를 실제 Groq 실행 기록으로 제시한 것은 아닙니다.


<details>
<summary>예상 결과와 다를 때만 확인</summary>

Groq 오류가 나면 키·모델 사용 권한·호출 한도를 확인합니다. .env를 바꾼 뒤 실행 중인 프로그램을 다시 시작합니다. 완료 상태가 아니거나 답변이 비면 성공한 턴으로 기록하지 않습니다. 추가 확인은 [문제 해결](../TROUBLESHOOTING.md)을 참고합니다.

## 4. Vibe 코딩에 유용한 프롬프트

```text
현재 1차시의 INSTRUCTIONS 문자열를 확인해 줘.
실무 목표는 업무 규칙과 출력 형식이 있는 IT 상담 초안이다.
교안의 같은 입력을 사용해 현재 결과와 변경 후 예상 결과를 비교해 줘.
수정은 해당 위치 한 곳으로 제한하고, 인증·소유권·성공 턴 저장 원칙은 유지해 줘.
변수의 출처와 호출 순서를 짧게 설명하고, 모델 응답 문장과 고정 상태 값을 구분해 줘.
.env, 비밀번호, 토큰은 출력하지 마.
```

### 복습 과제

원인을 단정하는 답변과 확인 질문을 먼저 하는 답변 중 실제 상담에서 쓸 초안을 고릅니다. 기준을 INSTRUCTIONS 한 곳에 보완하고 같은 문의로 출력 항목·사실 반영을 비교하세요.

입력과 예상 결과 중 실제로 확인한 항목을 짧게 남깁니다. 실제 직원의 정보 대신 수업용 가짜 문의를 사용합니다.
