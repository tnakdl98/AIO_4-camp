# 예상 결과와 다를 때

## 검은 화면 또는 빈 화면

파일 미리보기가 아니라 Streamlit CMD에 표시된 브라우저 주소를 엽니다. Ctrl+Shift+R 또는 새 시크릿 창으로 확인하고, CMD의 오류를 봅니다. main.py가 있는 폴더에서 실행했는지 확인합니다.

```bat
python -c "from pathlib import Path; print(Path('main.py').resolve())"
```

## Groq 키·권한·한도 오류

GROQ_API_KEY가 실제 키인지, 모델이 openai/gpt-oss-20b인지 확인합니다. SDK의 주소는 https://api.groq.com/openai/v1 입니다. Groq 콘솔에서 모델 사용 권한과 호출 한도를 확인합니다. 프로그램은 자동 재시도를 하지 않습니다. 한도가 걸렸다면 잠시 기다린 뒤 같은 요청을 확인합니다. 키를 로그에 출력하지 않습니다.

## 미완료 또는 빈 답변

완료 상태가 completed가 아니거나 output_text가 비면 기록하지 않습니다. 아주 긴 입력을 줄여 시도합니다. max_output_tokens에는 답변 외 추론에 쓰는 토큰도 영향을 줄 수 있으므로 너무 낮추지 않습니다. 예제는 reasoning effort low와 1600을 사용합니다.

## 3~4차시 연결 오류

8000 백엔드와 Redis가 실행 중인지 확인합니다. 화면 .env의 API_BASE_URL과 Groq base_url을 혼동하지 않습니다. backend03과 backend04를 동시에 실행하지 않습니다. 4차시에는 정상 로그인 가능한 Supabase 계정이 필요합니다.

## 401·404·409·422 구분

401이면 앱 로그인을 확인합니다. 404는 없는 문의 또는 자기 계정에서 열 수 없는 문의입니다. 409는 질문 번호 충돌·동시 변경·턴 한도 중 현재 요청 조건을 확인합니다. 422는 요청 필드·문자 수·UUID 형식이 API 계약과 다릅니다. 오류가 났다고 성공 턴을 추가하지 않습니다.

## 재시도 입력창이 잠겨 있음

연결 실패·502·503은 확인 중인 질문을 같은 질문 다시 보내기로 처리합니다. 422 입력 오류나 409 한도·조건 충돌은 입력창을 다시 열고 이유를 안내하므로 질문을 고치거나 다른 문의로 이동합니다. 다른 문의로 이동하려면 이 요청을 먼저 확인합니다. 4차시에서 계정을 바꾸면 미확정 질문은 삭제됩니다. 실패 예약은 한 번 소모되므로 재시도 전에 실패 버튼을 다시 누르지 않습니다.
