# 2차시. 문의 카드와 대화 이력을 결합하고 인계 메모 만들기

## 1. 학습목표

[수업 전 안내](../TODAY_GUIDE.md)를 먼저 읽습니다.

- 고정 문의 카드와 성공한 질문·답변을 다음 input에 함께 넣습니다.
- 대화 기록을 바꾸지 않고 담당자 인계 메모를 별도로 만듭니다.

### 앞 차시와 무엇이 달라지나요?

| 출발점 | 이번에 새로 완성할 기능 | 완료 산출물 |
| --- | --- | --- |
| 매번 독립된 단건 답변 | 고정 문의 카드와 변하는 상담 내용을 분리해 연속 상담 | 여러 턴 상담과 별도 인계 메모 |

기본 코드는 해당 기능이 정상 작동하는 완성 예제입니다. 실행 결과를 먼저 확인하고 업무 조건이나 표시 한 곳을 바꿉니다. 각 차시의 수정 과제는 다음 차시 실행의 전제 조건이 아닙니다.

## 2. 중요 알고리즘 및 코드를 읽을 때 반드시 알아야 할 내용

첫 문의에는 운영체제가 적혀 있었는데 후속 답변에서 같은 질문을 반복하면 상담 시간이 늘어납니다. 이제 제목·서비스·환경·영향 범위는 문의 카드에 고정하고, 새로 확인한 사실과 답변만 대화 이력에 쌓습니다.

`[문의 카드 1개] + [성공한 질문·답변] + [현재 질문 1개]`가 Responses API의 input입니다. 목록의 `+`는 항목을 순서대로 연결합니다. instructions는 이 목록과 별도로 매 요청에 보냅니다.

첫 상담 전 input은 2개입니다. 한 번 성공한 뒤에는 user와 assistant 두 메시지가 생겨, 두 번째 요청 input은 4개입니다. 카드 내용은 바뀌지 않지만 이력은 늘어납니다. 같은 브라우저 연결의 session_state를 사용하므로 브라우저 새로고침 뒤 복원까지 보장하지 않습니다.

인계 메모는 기존 상담을 읽어 만든 별도 결과입니다. 메모 생성용 질문과 답변을 상담 이력에 추가하지 않아 다음 상담에 요약 요청이 끼어들지 않게 합니다. 메모를 만든 뒤 성공 턴 수가 그대로인지 확인합니다. 새 상담이 성공하면 오래된 메모는 지우고 다시 만들게 합니다.

Groq는 현재 previous_response_id와 store 옵션을 지원하지 않으므로 이력을 직접 input으로 전달합니다. 문의 카드는 상담을 돕는 데이터이며 인증 정보나 서버 권한을 대신하지 않습니다.

### 핵심 코드

```python
def build_input(case, history, question):
    return [case_message(case)] + history + [{"role": "user", "content": question}]
```

전체 실행 코드는 [main.py](main.py)에 있습니다. 이번 수정 대상은 **handoff_question()**입니다. 준비된 인증·통신 코드를 모두 다시 작성하지 않고 현재 기능이 해결하는 문제를 확인합니다.

참고: [공식 Streamlit 챗봇 코드](https://github.com/streamlit/chatbot-template/blob/main/streamlit_app.py), [Groq 공식 Cookbook](https://github.com/groq/groq-api-cookbook).

## 3. 코드 제공

### 준비와 실행

Groq 콘솔에서 발급한 본인의 키를 .env의 GROQ_API_KEY에 입력합니다. GROQ_MODEL은 openai/gpt-oss-20b를 사용합니다. 키는 코드·교안·채팅에 적지 않습니다.

Windows CMD에서 현재 차시 폴더로 이동합니다. 경로는 실제 압축 해제 위치에 맞춥니다. 정상 수업 가상환경을 사용하며, 처음 환경 준비는 [서버·환경 안내](../BACKEND_GUIDE.md)를 따릅니다. **기존 .env가 있으면 copy 명령을 생략**합니다.

```bat
cd /d C:\AI4\Groq_MultiTurn_Morning\lesson02
python -m pip install -r requirements.txt
copy .env.example .env
notepad .env
python -m streamlit run main.py --server.address 127.0.0.1 --server.port 8501
```

브라우저에서 http://127.0.0.1:8501 을 엽니다. main.py 파일 미리보기가 아니라 이 주소가 실행 화면입니다. 화면 서버 종료는 해당 CMD의 Ctrl+C입니다.

### 실습 순서

1. 문의 카드의 제목은 `VPN 접속 문의`, 서비스는 VPN, 환경은 Windows 11, 영향 범위는 **팀 전체**로 선택하고 **문의 카드 시작**을 누릅니다.
2. `집에서는 접속되는데 회사 와이파이에서는 연결 시간 초과가 납니다.`를 전송합니다.
3. `같은 와이파이의 동료 3명도 같습니다. 모바일 핫스팟에서는 접속됩니다.`를 이어 전송합니다. **Groq에 전달한 input**을 펼쳐 문의 카드, 첫 질문, 첫 답변, 현재 질문 순서를 봅니다.
4. **담당자 인계 메모 만들기**를 누릅니다. 성공 턴 수가 바뀌지 않는지 확인하고 아래 예시와 비교합니다.
5. main.py의 `handoff_question()` 한 곳을 아래 함수로 교체합니다. 현재 함수는 세 항목의 한 문장 요약만 요청합니다. 수정 후 **담당자 인계 메모 만들기**를 다시 눌러, 다음 담당자 조치에 확인 방법이 추가되는지 비교합니다.

```python
def handoff_question():
    return "상담을 [확인된 사실], [미확인 사항], [다음 담당자 조치]로 정리하세요. 이미 시도한 조치는 반복 권고하지 말고, 다음 담당자 조치에는 확인 방법도 한 가지 적으세요."
```

6. **연결 실패 실습**을 펼쳐 **다음 상담 한 번 실패시키기**를 누르고 `추가로 확인할 것이 있나요?`를 전송합니다. 오류가 나도 성공 턴과 말풍선은 그대로입니다. 같은 질문을 다시 입력하면 이번에는 정상 호출합니다. 이 버튼은 Groq에 보내기 전 연결 실패만 흉내 냅니다.

### 예상 결과

| 시점 | 성공 턴 | 상담 말풍선 | 다음/직전 input |
| --- | ---: | ---: | --- |
| 카드만 생성 | 0 | 0 | 첫 요청은 카드 + 질문 = 2개 |
| 첫 상담 성공 | 1 | 2 | 첫 요청 input 2개 |
| 두 번째 상담 성공 | 2 | 4 | 두 번째 요청 input 4개 |
| 인계 메모 생성 | 2 그대로 | 4 그대로 | 별도 메모 표시 |
| 실패 버튼 후 질문 전송 | 2 그대로 | 4 그대로 | 오류 안내, 실패 질문 미기록 |
| 같은 질문 재입력 후 성공 | 3 | 6 | 현재 질문을 한 번만 기록 |

**인계 메모의 AI 답변 예시**

```text
[확인된 사실]
Windows 11의 회사 와이파이에서 본인과 동료 3명이 VPN 시간 초과를 겪고, 핫스팟에서는 접속됩니다.
[미확인 사항]
회사 네트워크에서 같은 시간에 VPN 장애가 있었는지는 확인되지 않았습니다.
[다음 담당자 조치]
사내 IT 문의 채널에 네트워크별 차이와 발생 시각을 전달해 확인을 요청합니다.
```

문장 대신 사실이 맞는지를 봅니다. 핫스팟에서도 안 된다고 뒤집거나 방화벽 문제라고 확정하면 재검토합니다. 함수 수정 후에는 담당자 조치에 구체적인 확인 방법이 추가되는지를 비교합니다. 새 문의 카드를 누르면 이력·카드·메모가 함께 초기화됩니다.

### 복습 과제

화상회의·Windows 11 카드로 새 상담을 두 턴 진행한 뒤 인계 메모를 만드세요. 카드 정보와 사용자가 이미 시도한 조치가 반영되고 인계 메모가 상담 턴을 늘리지 않는지 확인하세요.

입력과 예상 결과 중 실제로 확인한 항목을 짧게 남깁니다. 실제 직원의 정보 대신 수업용 가짜 문의를 사용합니다.
