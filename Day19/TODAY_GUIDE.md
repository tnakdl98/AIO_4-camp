# 사내 IT 문의를 이어 받는 상담 도우미

## 오늘 만들 결과물

“VPN이 안 됩니다”라는 문의를 받은 뒤, 이미 확인한 환경과 조치를 기억하고 다음 질문을 이어가는 상담 도우미를 만듭니다. 마지막에는 로그인한 계정의 문의만 열 수 있습니다. 예제의 운영 안내는 수업용이며 실제 회사의 정책이 아닙니다.

## 오늘의 진행 순서

| 차시 | 새로운 책임 | 예상 완료 결과 |
| --- | --- | --- |
| 1 | 답변 품질과 출력 기준 | 증상 요약·확인 정보·다음 조치가 있는 초안 |
| 2 | 고정 카드와 변하는 상담 이력 | 연속 상담 2턴 + 별도 인계 메모 |
| 3 | 서버가 컨텍스트를 소유 | 새 시크릿 창에서도 문의 ID로 두 턴 복원 |
| 4 | 계정별 접근 제어 | A 문의는 A만 열고 B 요청은 404 |

출력 기준, 상태 설계, API 자원, 권한이라는 서로 다른 문제를 같은 업무 사례로 해결합니다.

## 시작 전 확인

- Groq 콘솔에서 사용할 키와 openai/gpt-oss-20b 사용 권한을 준비합니다. 실제 키는 .env에만 입력합니다. 사용량과 한도는 본인 계정에서 확인합니다.
- 1차시는 CMD, 2~4차시는 Streamlit 화면을 사용합니다. 3차시부터 Redis와 FastAPI를 실행합니다.
- 4차시는 기존 Supabase Auth의 정상 로그인 가능한 수업용 A·B 계정이 필요합니다. PostgreSQL 테이블 준비는 이번 오전 범위에서 하지 않습니다.
- .env는 각 실행 폴더에서 읽습니다. 화면이 백엔드를 쓰는 3~4차시는 화면 폴더에 Groq 키를 넣지 않습니다.
- 설치·계정 준비는 실습 시작 전에 마칩니다. [환경 안내](BACKEND_GUIDE.md)를 먼저 확인합니다.

## 완료 확인

각 차시 README의 **예상 결과**와 비교합니다. AI 문장은 다를 수 있지만 턴 수, input 개수, HTTP 상태와 접근 권한은 정해진 기준을 따라야 합니다. 마지막으로 A의 문의 ID를 B가 열었을 때 404가 나고 기록이 노출되지 않는지 확인합니다.
