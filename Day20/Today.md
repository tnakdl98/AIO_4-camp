# 오늘 수업 안내 — Streamlit 실시간 생성 UX

## 오늘 만들 결과물

사내 IT 문의를 입력하면 **AI 답변이 만들어지는 동안 말풍선이 조금씩 채워지는 화면**을 만듭니다. 첫 화면에서는 전체 답이 완성된 뒤 표시됩니다. `render_answer()` 함수 한 곳을 바꾼 뒤 같은 질문으로 비교합니다.

이전 멀티턴 수업의 질문·답변 목록 전달 원리를 이어 사용합니다. 오늘 새로 확인할 것은 ‘무슨 답을 하는가’에 더해 ‘언제부터 답을 읽을 수 있는가’입니다.

## 오늘의 진행 순서

| 차시 | 진행 내용 | 눈으로 확인할 결과 |
| --- | --- | --- |
| 1 | 한 번에 표시하던 답변을 스트리밍으로 변경 | 완성 전에 글자가 나타남 |
| 2 | 첫 텍스트까지의 시간과 전체 시간 측정 | 서로 다른 두 시간 값 |
| 3 | 요청·수신·완료 상태 안내 | 기다리는 이유를 알 수 있는 문구 |
| 4 | 중간 끊김과 재전송 처리 | 부분 답변 경고와 새 시도 |
| 5 | 긴 답변의 읽기 흐름 개선 | 먼저 할 조치가 읽기 쉬운 화면 |
| 6 | 기존 인증·저장 서버에 스트림 연결 | 로그인한 사용자의 생성·저장 흐름 |
| 7 | 체감 속도와 답변 유용성 피드백 | 응답별 구분된 평가 |
| 8 | 같은 조건으로 UX 비교 | 관찰 근거와 개선안 |

## 시작 전 확인

기존 Python 환경과 Groq API 키를 준비합니다. 1차시는 `lesson01/main.py`를 실행하며 별도 FastAPI 서버를 시작할 필요는 없습니다. 키는 이 비교 화면을 실행하는 서버의 `.env`에서 읽습니다.

압축을 `C:\AI4\KDT_Streamlit_Streaming` 폴더에 풀고 [1차시 교안](lesson01/README.md)의 실행 순서를 따라갑니다. 이 화면의 대화는 현재 연결의 임시 기록입니다. 기존 서버 상담 화면의 저장 기록과는 구분합니다.

## 완료 확인

다음 입력으로 먼저 원래 화면을 봅니다.

> Windows 11 노트북에서 사내 VPN 연결이 30초 후 시간 초과됩니다. 집에서는 정상입니다. 먼저 확인할 항목 4개를 순서대로 알려 주세요.

함수를 바꾼 뒤 `비교용 새 대화`를 누르고 같은 질문을 보냅니다. 전체 답변이 완성되기 전부터 문장을 읽을 수 있고, 끝나면 완료 시간이 보입니다. 답변이 아주 빠르면 차이가 작을 수 있으므로 충분한 설명을 요청해 비교합니다.

후속 질문 ‘같은 팀원 3명도 동일한 증상입니다. 먼저 확인할 공통 원인은 무엇인가요?’를 보내면 앞선 대화가 남고 새 답이 이어집니다. 전체 생성 시간이 반드시 짧아지는 것은 아닙니다.

이번에 만든 텍스트 생성기와 정상 완료 확인 코드는 다음 시간의 최초 텍스트 시간 측정에 사용합니다.
